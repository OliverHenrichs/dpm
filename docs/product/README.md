# docs/product/

What DancePatternMapper does for the user, one living spec per feature area. The format and rules
are in [`docs/README.md`](../README.md).

Start with [`overview.md`](overview.md).

| File                                           | Area                                                                       |
| ---------------------------------------------- | -------------------------------------------------------------------------- |
| [`overview.md`](overview.md)                   | Every feature area in a line, and the principles across them               |
| [`lists-and-figures.md`](lists-and-figures.md) | Lists, figures, types, levels, tags, modifiers, rhythm, templates          |
| [`map.md`](map.md)                             | Timeline and network views, filtering, dragging, editing from the Map      |
| [`reels.md`](reels.md)                         | The Reels tab                                                              |
| [`sharing.md`](sharing.md)                     | Publish, subscribe, members-only lists, handover, suggestions, reports     |
| [`video-tools.md`](video-tools.md)             | Shorten, anonymize, transcribe, suggest a name and description, put online |
| [`settings.md`](settings.md)                   | Styles, app icon, languages, on-device models, import and export           |
| [`glossary.md`](glossary.md)                   | Dance terms and the app's own words                                        |

A rule marked _No test yet_ in a spec is a gap worth closing, not a rule that may be broken.
